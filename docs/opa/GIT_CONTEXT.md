# Git context — PR9a

See [PR9b explicit task worktrees](WORKTREES.md) for the subsequent setup and launch-binding implementation. The description below records the PR9a baseline.

This is the first, read-only step of [PR9 / #18](https://github.com/irodger/omni-pixel-agents/issues/18). Explicit worktree creation/attachment, launch binding and management remain PR9b. The issue stays open until those steps and their acceptance checks are complete.

New TaskRun executions capture a version-1 Git observation before starting and another after process close. These snapshots survive history/restart and do not change when a later query observes a different branch or commit. Historical attempts without evidence display “not recorded”; no past HEAD is inferred from today's repository. Interrupted recovery retains the start snapshot and does not invent a finish snapshot.

The observation records canonical cwd, worktree root, per-worktree Git directory, common Git directory, branch or detached HEAD, commit when present, dirty/conflict flags and submodule identity. An unborn branch has no commit. Non-Git directories and unavailable, bare, deleted or unreadable contexts are explicit states, never guessed clean repositories. A HEAD/branch/root identity change during the read yields an unstable observation. These are sequential metadata reads, not an atomic filesystem snapshot: file edits can still race with status, and symlinks can change after observation. PR9b must revalidate canonical repo/worktree identity and bind the actual launch cwd before claiming isolation.

Current task cards and historical summaries expose a separate “Inspect current Git context” observer action. It does not overwrite start/end evidence. The UI shows identity differences from the saved launch context; identical dirty flags do not imply identical files. The `opaGitContextRequest` / `opaGitContextState` exchange is supported by WebSocket and the VS Code bridge, limited to known office/task projects under the existing observer visibility policy. No arbitrary-path query, file contents, remote URLs or Git credentials are returned. No new HTTP endpoint is introduced.

Git subprocesses use fixed arguments, no shell, bounded time/output, optional locks disabled, and fsmonitor/untracked-cache extensions and configured clean/process filters disabled. Inherited `GIT_*` routing/config variables are removed; normal Git ownership checks remain enabled. Reads never perform checkout, commit, push, merge, fetch, prune or cleanup. Status ignores submodule contents and reports only the containing worktree's tracked/untracked changes; it does not run submodule commands. Too-large output, unsupported Git flags or command failures leave the context unavailable. When configured clean/process filters are disabled, the dirty flag is unknown: comparing raw bytes cannot establish the repository’s normal filtered status. Conflicts still come from index status. Git must be installed separately; it is optional for existing non-Git task execution.

Task execution, permissions, cancellation, saved journals, IDE navigation and the one-run-per-project limit keep their existing behavior. PR9a creates no worktrees and does not offer destructive cleanup. PR9b must handle explicit create/attach consent, branch collisions, external worktree ownership, canonical path/cwd validation, dirty retention and journal/IDE cwd binding. PR10 supplies the diff viewer; PR11 supplies actual quality-check evidence.

Fixture repository tests cover nested/canonical paths, unborn/detached HEAD, linked worktrees with distinct Git directories, deleted worktrees, dirty/conflicted retention, fsmonitor/filter suppression, index bytes/mtime preservation and immutable snapshots after restart. Process fixtures verify start/end observations when Git is unavailable; rendering tests cover unknown old attempts, escaped paths and observer-only controls. No live or paid model execution is claimed.
