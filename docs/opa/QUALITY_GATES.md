# Local Quality Gates (PR11)

Issue: [#20](https://github.com/irodger/omni-pixel-agents/issues/20).

Open **Quality Gates** in a completed task attempt or its saved summary. Refresh loads host-owned check configuration and observations. Add a named check with an **absolute executable path**, JSON string-array argv, and timeout (100–600,000 ms). Configuration belongs to the OPA host's work-state storage, not a repository file. Saving never executes a command. Node 20 or newer remains required; no new optional runtime is installed.

For npm scripts, use your absolute Node executable with argv containing your absolute npm CLI script path and script arguments, or another explicitly reviewed executable. There is no implicit shell, PATH resolution, command discovery or dependency installation. Windows `.cmd` files are not implicitly wrapped in a shell. An explicitly selected shell or project script retains all its normal local powers.

**Review run** produces a 60-second, single-use plan with exact executable/argv, timeout, canonical attempt cwd, recorded base commit, current HEAD, configuration/executable digests and current file fingerprint. **Approve and run once** is a separate action. The host verifies the plan again, consumes it before dispatch, and persists a reservation before spawning. Changed config invalidates prepared plans. Missing executables can be reviewed, but produce an unknown/not-started observation rather than a fabricated exit code. Reruns always require a new review and confirmation. Reconnects, reads, replayed requests and restart recovery never launch a check.

Checks use the saved attempt's exact Git identity/cwd, including an explicitly bound worktree; they do not fall back to a newer task binding. One owned check or agent run may execute per repository, across registered worktrees. Skip is an explicit observation without a process. Cancel addresses the exact owned check run. On POSIX, timeout/cancel terminates the owned process group, then forces termination; on Windows it terminates the direct child only. Detached descendants on Windows are not covered. Host shutdown requests cancellation; host restart marks previously running observations unknown and never adopts or kills unknown processes.

## Evidence

Each bounded record carries independent check-run and task-attempt IDs; exact config, command, cwd, base/HEAD and fingerprint; reservation/spawn/end times; observed exit/signal; timeout/cancel/not-started reason; and up to 8,192 characters per stdout/stderr stream. At most 200 observations are retained, removing terminal records first. Configuration is capped at 100 projects and 20 checks per project. Private configuration and logs require the control connection or VS Code extension. Public work snapshots do not include them. Logs render as text; they may contain secrets produced by your approved program.

`passed` means an observed process exited zero. **Test execution and test count are unreported**: neither names, console text nor zero exit establish that tests ran. Failed, skipped and unknown remain distinct. `stale` is shown separately from the recorded process outcome, including when the program changes files during execution. Refresh verifies current freshness; until refreshed the display is a dated observation. Historical Inbox check entries explicitly describe recorded outcomes. Real session/process observations feed Event History/Timeline under `opa-quality`, labelled as a local process rather than an AI agent. No `tool.started` is emitted before an actual child spawn. An unavailable terminal write leaves the last durable reservation unknown after ownership loss; a Timeline write failure is labelled where persistence remains available.

## Fingerprint limits and risks

Fixed read-only Git queries enumerate tracked and nonignored untracked files and index stages. Raw complete file bytes (including binary files), modes, missing tracked paths, symlink text and Git identity/HEAD/branch are hashed. Clean/process filters, textconv and external diff tools are not executed for fingerprinting. Symlink targets are not followed intentionally. Submodules and special files refuse a plan. Bounds: 2,048 paths, 32 MiB per repository file, 128 MiB total, 256 MiB executable, bounded Git output/time and a best-effort 5-second enumeration budget. Large or unreadable trees fail visibly rather than omit content silently.

This is **not a sandbox, filesystem snapshot or hermetic build**. Reads/checks are sequential; concurrent edits (including ABA changes), path replacement races, environment, ignored dependencies/files, external symlink targets, imported code outside the worktree and global executable dependencies cannot be fully covered. Slow filesystem calls can exceed the best-effort budget. Checks may modify files, access networks, spend money or start subprocesses according to their approved commands and normal OS privileges. Review scripts/configuration before approving. There is no automatic retry, paid agent restart, merge, publish, public tunnel or SaaS runner.

Fixtures in the test suite are disposable local repositories and processes labelled “Fixture”; production never fabricates fixtures, test counts or history.
