# Attention Lite (planned PR3)

The **Attention Inbox** tab unifies current source-agent blocks/errors/completions with task permission blocks and terminal run results, including failed, cancelled and interrupted runs. Project selection filters the list. Blocks come first, then errors and unread results, oldest known time first; unknown waiting times have no fabricated timer. Campus/legacy-office entry counts, the overview preview and Ambient use the same projection.

Open result / Review block only navigates. **Mark read** is a separate browser-local action, available only for terminal results. It never answers an approval, starts/retries work or hides an unresolved block. Exact task/run/state keys distinguish later attempts. Read marks use the existing 2,000-entry browser preference and survive reload where local storage is available; in restricted storage they remain in memory. They are not host-wide or cross-device state (PR8).

New task executions retain the exact terminal OPA event ID. This suppresses an identical source result in the unified list and lets explicit read acknowledgement cover the two representations. Older runs without that evidence are not correlated by names or time. Separate pending permission representations are not silently merged: the portable v0.1 source permission event has no individual approval ID. ACP choices remain on the authenticated current-run task controls; native approvals stay in their source client. Stale/unavailable source sessions remain visible navigation failures rather than invented chats.

Inbox rendering/reconnect is a passive projection of the latest host snapshots. Offline state is visible, and the existing host-required controls remain unavailable. Current/latest task executions are the input; immutable attempts, saved event history, durable attention reconciliation/snooze and actual quality-check observations belong to later increments. No system notification or cloud service is added.

Verification: projection tests cover exact evidence deduplication, unknown times, ordering and run/project-scoped read identity. The fixture browser suite covers repeated snapshots, result navigation without read acknowledgement, explicit read marks across reload and unresolved permission controls. Native/ACP process fixtures verify captured terminal event identity. No paid/live agent run is claimed.
