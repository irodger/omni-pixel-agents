# Local event history index (PR5)

The host now keeps a bounded, version-1 observation index in `opaHistory` in its existing namespaced state. It indexes the same normalized OPA v0.1/v0.2 envelopes used by producer and task journals; it does not introduce an alternative event contract or replace the source journals. Both standalone and VS Code use the shared file adapter. Hosts without optional history persistence hooks have only an in-process index.

## Recording, replay and limits

An observation is committed before its office/work projection. Native/ACP task observations retain task/run association with `origin: task-journal`; ordinary ingestion is `origin: ingestion`. Explicit host fixtures can use `origin: fixture`. These describe how an observation arrived, not proof of a live model run, a test passing or an invoice. Arbitrary producer fields cannot claim trusted origin or introduce command permissions. Known envelope/payload fields are retained; raw arguments, reasoning and unknown extra fields are omitted. Long message/error/name/title text is an explicitly labelled excerpt (`truncatedFields`, up to 4,096 characters); an individual stored entry cannot exceed 32 KiB. Source journals retain their original normalized contents.

The index preserves append/observation order via a monotonically increasing `ordinal` and a host `observedAt`; source timestamps are preserved but never used to reorder it. Stable high-water marks are scoped by provider/session/agent/stream and survive host restart and window retention. Replaying the same normalized journal cannot append duplicate observations. Producer restart uses a new stream ID. Re-normalizing raw input with new IDs is still a new observation, as documented in FORMAT.md; no identity is guessed from text or timestamps.

The retained event window is at most 2,000 entries or 4 MiB, dropping the oldest prefix first. `droppedThrough` explicitly identifies the unavailable prefix; an expired cursor returns an error rather than silently jumping to a different page. Original journals and TaskRun records are not deleted. Checkpoints and project association are retained independently of this window, with a limit of 4,096 stream keys. Reaching that limit fails visibly for a new stream instead of forgetting deduplication state; there is no automatic checkpoint reset, destructive cleanup or hidden retry. This local JSON index is a single-host MVP, not a high-throughput collector. It uses the existing atomic file replacement; no power-loss or multi-writer durability guarantee is claimed.

Corrupt state, unsupported versions, failed writes and conflicting source/project identity do not become an empty successful history. Strict history reads report errors, and the file adapter refuses to overwrite an unreadable state file. Native process observations are already appended to their owned run journal before indexing; index failure is visible and never triggers an alternate paid attempt. An office projection may be restored by passive replay after restart while the durable index skips its already recorded events. Projection bookkeeping is shared between office instances on one host to avoid duplicate live characters.

## Retrieval and export

Bearer-authenticated `GET /api/opa/history` requires `projectPath`. Optional filters are `taskId`, `runId`, `provider`, `sessionId` and `eventType`; unknown associations remain absent. `limit` is 1–50 (default 20), and `before` is the last ordinal from the preceding page. Responses contain newest-first `entries`, optional `nextCursor` and `droppedThrough`. Read results are copies. The service never accepts a journal filename or arbitrary filesystem path to read.

`format=jsonl` exports that bounded page oldest-first with the original OPA envelope plus `opaHistory` metadata, including origin, truncation labels and the dropped-prefix marker. This is a labelled excerpt, not a guarantee that a retained page contains the session start needed for standalone replay. Use original normalized producer/task journals for complete restoration; missing events/session starts are never fabricated.

Observer WebSocket and embedded requests use `opaEventHistoryRequest`/`opaEventHistoryPage`, with the same local visibility as current task snapshots. This is an explicit read-only query even for tokenless WebSocket observers. Other anonymous commands remain denied. Requests, export, office replay and retention have no route to assignment, launch, permission reply, paid retry or merge. A response error is distinct from an empty successful history. Timeline/Inbox presentation is left for the following increments.

No source-journal scan runs automatically. Existing normalized histories can be replayed through the existing bridge. Strict replay still rejects malformed JSON/OPA with a line number. Explicit `replay --allow-incomplete-tail` may skip only an unparsable unterminated final JSON fragment, with a visible warning; malformed complete lines and valid JSON with an invalid OPA schema still fail. The streaming reader handles chunk boundaries/CRLF and bounds individual JSON lines. Tail tolerance is unavailable for raw Codex/OpenCode normalization.

## Verification

Fixtures cover durable replay/restart, provider isolation, producer restarts, stable observation order, window gaps and cursor expiry, checkpoint capacity, filtering/pagination, JSONL provenance, excerpt/redaction behavior, failed persistence and corrupt/unsupported state. File-adapter tests cover reload, unrelated saves preserving the index and refusing to overwrite an unfinished state file. HTTP history routing is exercised in-process (without a listener) for auth, bounds, filters, export and expired cursors; WebSocket observation uses the shared handler directly. Bridge subprocess tests use fixture stdin without a network URL and cover strict/tolerant tails and schema errors. No paid/live model session is claimed.
